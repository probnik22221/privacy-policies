## 2. Information We Process

### 2.1. Information stored only on the user's device

The Application stores the following information locally on the user's device:

- reading history and cards drawn during readings;
- questions, descriptions of situations, and personal notes;
- drafts of unfinished readings;
- the daily card and information about whether it has been revealed;
- achievements, progress, visit streaks, and selected rewards;
- language and sound settings;
- a local indicator showing whether Dione PRO is available;
- the email address and authentication token after signing in to purchase or restore Dione PRO.

By default, reading questions, descriptions of personal situations, personal notes, and journal contents remain on the device. The Dione PRO feature “The Oracle of Dione,” described below, is the exception: information is transmitted only after the user gives separate confirmation.

Local information may be deleted using the features available in the Application, by clearing the Application's data in the device settings, or by uninstalling the Application. The available deletion method may depend on the device's operating system.

### 2.2. “The Oracle of Dione” information

If a user with active Dione PRO opens “The Oracle of Dione” and explicitly agrees to the transfer, the Application sends the following to the Controller's server:

- the user's original question, if provided;
- the spread name, cards drawn, their positions, and the interpretation generated by the Application;
- the user's questions and earlier messages in the current conversation;
- the selected response language.

This information is sent to **Yandex AI Studio (Yandex Cloud)** solely to generate a personalized response with YandexGPT. Users should not include names, contact details, health information, payment information, or other sensitive information in the conversation. Dione Tarot's server logic does not store AI conversation content in its database. Technical processing by Yandex Cloud is governed by that provider's terms and privacy documents.

### 2.3. Dione PRO account information

An account is not required for ordinary use of the Application. If a user signs in to purchase or restore Dione PRO, the Controller may process:

- the user's email address;
- a hash of the one-time login code, the number of verification attempts, and the code's validity period;
- a hash of the authentication token and the duration of the user session;
- the dates on which the account was created and updated;
- the expiration date of Dione PRO access.

A one-time login code is valid for 10 minutes. An authenticated session is created for up to 90 days. Expiration of a code or session means that it can no longer be used to sign in, but it does not necessarily mean that the related technical record is immediately physically deleted.

### 2.4. Purchase information

When a user purchases Dione PRO, the following information may be processed:

- the selected subscription plan;
- the transaction amount and currency;
- the payment identifier and payment status;
- for Aptoide purchases, the purchase token, order identifier, subscription product identifier, renewal indicator, and verified expiration time;
- the purchase-attempt identifier;
- the dates on which the transaction was created, paid, applied, and updated;
- the period of Dione PRO access granted to the user;
- a technical payment confirmation URL.

The payment provider depends on where the Application was obtained: **Aptoide** processes in-app subscriptions in the Aptoide version, while **YooKassa** processes payments in the RuStore version. Neither the Application nor the Controller's server receives or stores the full card number, card expiration date, or card security code.

### 2.5. Technical information

When the Application communicates with the Controller's server, the server, hosting provider, and network security systems may automatically process standard technical information, including the IP address, request date and time, device or client type, network request headers, and error information.

The Dione Tarot server logic does not record the user's email address, request contents, authorization headers, or free-form payment-provider responses in error logs. Separate technical logs may nevertheless be created by the hosting infrastructure in accordance with its configuration and applicable law.

The Application does not use advertising SDKs and does not access geolocation, contacts, the camera, or the microphone. In the Aptoide version, the Aptoide Billing SDK may process limited device, application, transaction, and SDK diagnostic information needed to provide payments, prevent fraud, and monitor billing reliability under Aptoide's own privacy terms.

## 3. Purposes of Processing

Information is processed only for the following purposes:

- sending and verifying a one-time login code;
- creating and maintaining a user session;
- purchasing, verifying, and restoring Dione PRO access;
- processing and confirming payments;
- preventing duplicate charges and resolving incomplete payments;
- performing obligations to the user;
- responding to requests and resolving technical errors;
- complying with legal, accounting, and tax requirements;
- protecting the security of the Application and server infrastructure.
- providing a personalized response in the Dione PRO feature “The Oracle of Dione” at the user's request and with the user's consent.

Information is not sold, disclosed to advertising networks, or used for marketing messages without the user's separate consent.

## 7. Retention

The Controller retains information only for as long as necessary for the stated purposes, unless a longer period is required by law:

- local information remains on the user's device until the user deletes it;
- a one-time login code can be used for 10 minutes;
- an authenticated session remains valid for up to 90 days;
- the email address and Dione PRO access information are retained while necessary to provide and restore purchased access;
- payment information is retained for the periods necessary to confirm purchases, resolve disputes, and comply with accounting and tax obligations;
- technical logs are retained for the period determined by security settings and the hosting provider.
- Oracle conversation content is not stored in the Dione Tarot database and is used by the server only while generating a response; Yandex Cloud's technical processing periods are determined by that provider's documents and service settings.

When processing purposes have been fulfilled, information is deleted, anonymized, or restricted unless continued retention is required by law or is necessary to protect the rights of the Controller or the user.

## 8. Information Security

The Controller applies reasonable legal, organizational, and technical safeguards, including:

- transmitting information over HTTPS;
- storing one-time codes and server-side tokens as cryptographic hashes;
- limiting the validity period of login codes and user sessions;
- limiting the number of one-time code verification attempts;
- using unique identifiers to prevent duplicate payment creation;
- restricting access to the server and database;
- minimizing information included in error logs;
- verifying payment status directly with the payment provider.
- keeping the Yandex AI Studio access key on the server, verifying active Dione PRO on the server, limiting request sizes, and excluding AI conversation content from application error logs.

Despite these safeguards, no method of electronic transmission or storage can guarantee absolute security.
